# Apex LineUp — F1 Driver Ranking Lab

An interactive Formula 1 driver ranking tool. Explore how the order changes when you choose a season or year range, adjust the importance of different performance metrics, and compare multiple ranking setups side by side.

## Features

- Rank drivers using 17 adjustable metrics, including wins, win rate (wins divided by Grand Prix starts), team points share, podium rate, qualifying position, race pace, and consistency.
- Use presets or set your own metric weights.
- Switch between historical championship points and points recalculated under today's Grand Prix scale.
- Filter by season, year range, team, nationality, era, and minimum starts.
- Choose and order 2–10 drivers, find matching weights, and explore feasible weight ranges while keeping that order.
- Save up to six ranking setups for side-by-side comparison and share weights with a code.
- Switch between English, 简体中文, 日本語, Français, 한국어, and हिन्दी.

## Run locally

This is a static website with no build step. Serve the repository directory with a local web server, then open the address it prints:

```bash
python -m http.server 8000
```

Open [http://localhost:8000](http://localhost:8000). Opening `index.html` directly as a file may prevent the browser from loading the JSON data.

## Data and interpretation

The bundled data combines historical F1DB records with OpenF1 data for recent seasons. The ranking view normalizes metrics and applies the selected weights; changing the metrics or time range can change the result. Some telemetry-based metrics are unavailable for older seasons, so cross-era comparisons should be read with the displayed data coverage in mind.

Data and field definitions are in `data/`, including `metric_schema.json` and the quality reports. F1DB: https://github.com/f1db/f1db · OpenF1: https://openf1.org

The **Current-rules points** switch applies 25–18–15–12–10–8–6–4–2–1 to each eligible Grand Prix result, then updates total points, points per start, and team points share. Sprint and fastest-lap points are excluded, as are historical shared-car drives. Results after the site's existing race cutoff are ignored. The source is [F1DB v2026.18.0](https://github.com/f1db/f1db/releases/tag/v2026.18.0); `data/current_points.json` is generated from its CSV archive by `scripts/build_current_points.py`. This changes the scoring scale, but does not equalize car performance, reliability, or the number of races.

**Team points share** uses [F1DB v2026.18.0](https://github.com/f1db/f1db/releases/tag/v2026.18.0) Grand Prix results. For each driver–constructor stint it divides the driver's race points by that constructor's points in the same races, including only races where another driver started for the constructor. Shares are averaged across stints using comparable starts; at least 10 such starts with a positive team-points denominator are required. Zero denominators and pre-1958 seasons remain missing. The current-rules switch recalculates both sides of this ratio from the same 25–18–15–12–10–8–6–4–2–1 scale; sprint, fastest-lap and shared-car points are excluded. `data/team_points_share.json` is generated by `scripts/build_team_points_share.py` under the site's existing race cutoff. Early independent entrants sometimes used the same constructor, so this is an approximation of team contribution, not a direct measure of driver skill. A high share can also reflect a weaker teammate.

This project is an exploratory visualization, not an official Formula 1 ranking.

In Reverse ranking, the vertical slider at the left of each metric adjusts its weight. The horizontal interval on the right uses the same metric color as the main ranking and shows feasible values while the other weights keep their current proportions. Moving a slider redistributes the remaining weight and updates all intervals. These intervals are slices through the feasible weight space, not independent global bounds; endpoints from different rows cannot generally be combined.

Grand Prix pole-position counts come from the `polePosition` flag in the [F1DB v2026.18.0](https://github.com/f1db/f1db/releases/tag/v2026.18.0) race-results CSV. Sprint qualifying poles are excluded. `data/pole_positions.json` is generated by `scripts/build_pole_positions.py` and follows the same race cutoff as the bundled season snapshot.

The four presets each total 100 weight units. Balanced spreads weight across career results, per-start efficiency, race outcomes, team points share, and recent telemetry. Pure pace emphasizes qualifying position, poles, race pace, and lap consistency. Racecraft emphasizes positions gained and overtaking, with a small team points share weight. Reliability emphasizes finish rate, consistent lap times, and sustained results. GP starts have a small weight in every preset to keep a handful of starts from dominating a career comparison; the minimum-start filter remains available. Some modern telemetry metrics and early team points share values are unavailable in historical seasons, so available weights are renormalized. These presets are interpretive choices, not estimates of intrinsic driver skill.
